The 4 Universal Case Study Beats & Visual Attachment
1. Problem / Idea
brokenState What was broken, missing, or being investigated before starting.
summary Plain-language context of why this problem mattered.
constraints List of real constraints (offline-first, zero errors, performance budget).
visuals[] Visual evidence of the problem: e.g. screenshot of the addictive screen time loop in Dhyan, photo of messy paper survey records in NFHS, or confusing legacy clinical tool in Audri.
2. Plan & Scope
framing How the project was scoped (commercial contract vs. applied R&D investigation).
deliverables List of tangible outputs produced (components, state machines, hardware tokens).
seams What was explicitly out of scope (e.g. backend integration handled by partner).
visuals[] Architectural boundary map: e.g. system topology diagram, information architecture map, or state machine schematic showing what is inside vs outside the design seam.
3. Design & System
overview High-level architecture of how the interface and flows actually work.
mechanics Key interactions, friction points, or state handling mechanics.
visuals[] The core interface choreography: Interactive sandboxes, scrubbed video walkthroughs, high-res UI flow carousels, or tactile friction sliders showing the system running.
4. Outcome & Learnings
summary What happened when deployed or tested.
metrics Real metrics or qualitative findings (or [Sanitized] if NDA).
reflection One sentence on what this taught you about this class of system.
visuals[] Real-world proof & deployment artifacts: Photo of the printed QR key in a physical room, screenshot of verified local device logs, or field survey in enumerator hands.
Detailed Specification

What Exactly a visual Block Entails

Every item in visuals[] (and heroVisual) is a structured object with 7 explicit properties:

Property Type / Options Description & Purpose
format static-frame
video-scrub
interactive-canvas
3d-model
explainer-figure
prototype-embed 		The execution medium:
• static-frame: High-res retina image / poster frame.
• video-scrub: Inline video whose timeline scrubs on scroll or plays on viewport enter.
• interactive-canvas: Procedural WebGL shader or interactive React canvas.
• 3d-model: Three.js/OGL scene with orbital or scroll-linked rotation.
• explainer-figure: Isometric or exploded system architecture flow.
• prototype-embed: Sandboxed live UI micro-component or interactive stub.
src string Asset file path (e.g. /assets/dhyan/token-hero.webp), video URL (H.264/WebM), 3D asset (.glb), or registered React/Astro component name (e.g. DhyanFrictionSimulator).
aspectRatio 16/9 | 21/9 | 4/3 | 1/1 | fullscreen Controls layout container sizing and prevents cumulative layout shift (CLS).
caption string Editorial caption underneath the visual explaining the systems significance of what is shown.
alt string Accessible plain-text description for screen-readers and SEO.
motion.behavior pinned-scrub
idle-loop
hover-reveal
user-driven
static 		How the visual animates:
• pinned-scrub: Scroll locks the viewport and scrubs the visual timeline.
• idle-loop: Subtle continuous breathing motion at rest.
• hover-reveal: Expands details or highlights data under cursor.
• user-driven: Direct interactive canvas (visitor clicks/drags).
• static: Traditional motionless display.
motion.driver scroll | pointer | time The clock or input controlling the animation (scroll position, mouse cursor, or GSAP ticker).
