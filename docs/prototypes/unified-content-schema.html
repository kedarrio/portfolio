The 4 Universal Case Study Beats
1. Problem / Idea
brokenState What was broken, missing, or being investigated before starting.
summary Plain-language context of why this problem mattered.
constraints List of real constraints (offline-first, zero errors, performance budget).
visuals[] Optional visual blocks (e.g. screenshot of problem loop, breakdown photo).
2. Plan & Scope
framing How the project was scoped (commercial contract vs. applied R&D investigation).
deliverables List of tangible outputs produced (components, state machines, prototypes).
seams What was explicitly out of scope (e.g. backend integration handled by partner).
visuals[] Optional system diagram, architecture map, or boundary flow.
3. Design & System
overview High-level architecture of how the interface and flows actually work.
mechanics Key interactions, friction points, or state handling mechanics.
visuals[] Core interface visual choreography (interactive sliders, WebGL, video walkthroughs).
4. Outcome & Learnings
summary What happened when deployed or tested.
metrics Real metrics or qualitative findings (or [Sanitized] if NDA).
reflection One sentence on what this taught you about this class of system.
visuals[] Optional real deployment photo, device in hand, or verification log.
